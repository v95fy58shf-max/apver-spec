# Contributing to Apver

Apver is currently a concept specification and provenance repository. Contributions should be precise and limited to what the repository actually defines.

## Issues and Pull Requests

- Use the bug form for errors in documents or repository infrastructure.
- Use the feature form for non-core improvements.
- Use the RFC form for core concepts, protocols, or compatibility proposals.
- Search for duplicates and never include secrets, tokens, or personal data.
- Keep each pull request focused, explain its motivation, link relevant discussion, update affected documentation, and complete the checklist accurately.

Documentation corrections may use an ordinary pull request. Changes to memory architecture, workflow protocol, runtime abstraction, permission model, marketplace protocol, package format, core terminology, or compatibility model require an RFC first.

Technical contributors retain appropriate attribution. Contributions must not remove, obscure, or retroactively alter the provenance recorded in `ORIGIN.md`, `VISION.md`, `ARCHITECTURE.md`, repository history, or the `concept-v0.1` release.
