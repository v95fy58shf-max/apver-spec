# Apver RFC Process

Requests for Comments provide a reviewable record for proposed core changes. An RFC is a proposal, not an approved decision.

An RFC is required for changes to memory architecture, workflow protocol, runtime abstraction, permission model, marketplace protocol, package format, core terminology, or compatibility model.

## Process

1. Copy `0000-rfc-template.md` to a file with the next available number and a concise title.
2. Complete every section and open a pull request marked as a proposal.
3. Link the related RFC Discussion or Issue and gather focused review.
4. Revise while preserving material objections and alternatives.
5. Record the final decision. Approval requires repository-owner review at the current concept stage.

Do not describe an RFC as accepted before its decision is explicitly recorded and merged. Ordinary pull requests cannot bypass this process.
